# 《余烬来信》系统与数据规划

本文件是未来在 Windows 上建库、写事件和制作界面的详细设计输入，不是已实现的游戏规格。依据 `main` 的 `c1dc162` 中确定性选择、敌方预告、首胜一次、通信／研究／信任因果链重新设计；废弃卡牌、牌组、三行动力、网页单人生存档和原作身份。

当前只编写规划，不安装引擎、不运行项目、不做数值模拟或开发验证。下文数值是首轮建库建议，需要未来实际制作时调整；不存在“已经平衡”或“已经可通关”的结论。剧情、地图与交接分工分别见同目录的其他规划文件；同一功能只建立一个权威数据源。

## 1. 系统边界与核心循环

### 1.1 固定规则

| 项目 | 规划基线 |
| --- | --- |
| 主角 | 林恩，固定女性、姓名、出身和核心经历；培养和立场由玩家决定 |
| 章节／年龄 | 根源 8、学艺 15、断裂 18、重建 23、真相 28、棋局 33、传承 40 岁 |
| 战斗队伍 | 林恩＋最多三名同伴；其他成员在安全据点待命 |
| 同伴 | 赫岚、米娅、赛洛、诺弥、温德；各三个个人任务 |
| 地图 | 正交俯视，48×48 像素格；正式版 40 张可玩地图 |
| 战斗 | 独立侧视、标准指令回合制；每名可行动者每回合一个动作 |
| 成长 | 等级上限 30；42 场主线能够提供全部必要成长 |
| 可选内容 | 14 场可选战斗，提供资源、装备或解法，不要求刷级 |
| 技艺 | 六系各八个，共 48 个基础技能；另有五个同伴协作技能 |
| 装备 | 武器、防具、饰品各一个槽位，各十种，共 30 件定义 |
| 首发 | 单机、离线、简体中文、键盘与鼠标；没有账号、联网和权限系统 |

第一章全部战斗为非致命训练或有成年人保护的驱离事件。失败返回教学准备，不产生儿童死亡。童年剧情中的危险必须由文本、退出选项和独立确认明确告知，不通过普通训练突然触发悲剧终局。

### 1.2 常规循环

1. 在据点查看来信、人物与任务，选择可选准备，配置队伍和技艺。
2. 在可见地图中调查、交涉、领取一次性资源，决定路线。
3. 危险区入口显示目标、预计敌群、必要准备、撤退规则并自动保存。
4. 完成固定遭遇或明确的剧情选择，结算人物、资源和事实。
5. 回到据点整备；重要结果写入年表，章节交接显示未完成内容。

地图敌人可见；击败后在本章内消失。宝箱与采集点领取一次。主线不出现随机遇敌、敌人无限刷新、重复首胜奖励或必须购买的通关门票。

### 1.3 明确排除

首版不制作饥饿条、装备耐久、随机疾病、复杂采集制作、随机地图、战斗中存档、自定义手柄系统、恋爱赠礼循环、铁人模式和多人功能。没有“善恶值”，不把全部选择合并成好人与坏人的单一标签。

### 2.1 角色定位

| 人物 | 可训练技艺 | 队伍职责 | 加入阶段 |
| --- | --- | --- | --- |
| 林恩 | 六系均可 | 按培养成为护卫、术士或救护者 | 第一章固定 |
| 赫岚 | 武技、岩术 | 承伤、保护、削弱前排 | 第二章 |
| 米娅 | 医术、寒术 | 恢复、净化、削弱危险动作 | 第二章 |

| 诺弥 | 焰术、岩术 | 反再生、设施干预、群体输出 | 第四章 |

人物的可训练范围来自经历，不由高属性自动扩大。林恩跨系学习需要相应导师或现场学习资格，但不依赖随机掉落。

林恩与赫岚构成最低通关配置。赫岚在主线中不可永久失去；短期离队事件必须安排在无需战斗的安全段，下一场强制战斗前回归。米娅可有短期离开与回归。米娅、赛洛、诺弥、温德的永久损失只出现在后期有风险说明的明确选择中，绝不由低关系数值自动触发。持续伤势不禁止保底二人上场。

| 根源 | 1 | 1、1、2、2、3、3 | 3 |
| 学艺 | 5 | 5、5、6、6、7、8 | 8 |
| 断裂 | 9 | 9、9、10、10、11、12 | 12 |

MZ 使用原生等级与经验字段，不建立第二套经验条。规划中的普通敌群经验设为 0，主线首胜事件自动通过当前版本的等级经验表补差额，并再次核对章末最低等级。主线奖励界面显示“本次主线成长：最低等级 X”，可选任务则明确显示“物资／装备／技能资格／剧情成果”，不显示误导性的经验奖励。若后续改为普通经验奖励，必须保留表中的保底，不同时执行两份增长奖励。

### 2.3 技能学习

- 每升一级获得 2 个培养点，等级 2–30 共 58 点。培养点总额由当前等级推导，不能反复读档领点。
- 林恩的四个基础动作“火种、石衣、止血、定步斩”由第一章教学授予，不占培养点。同伴加入时获得所属两系的第一个基础技能，也不占点。
- 每系按 1–8 顺序学习；上一技能、表内章节资格、学习阶段与培养点同时满足才可学习。四阶段为入门（等级 3，技能 1–2）、熟练（等级 8，技能 3–4）、专精（等级 17，技能 5–6）、导师（等级 25，技能 7–8）；等级 1 的教学授予是明确例外。各阶段单技能分别花 1、2、3、4 点，一系共 20 点。达到等级只开放学习上限，不自动授予技能或导师身份。
- 教学或剧情授予的技能不重复收费；其既有资格与基础技能不能通过重置兑换点数。
- 第二章的“护卫／术士／救护”是推荐分配方案，分别优先武技＋岩术、焰术＋风术、医术＋寒术；不是永久锁定职业。
- 安全据点可免费退还已花培养点并重新分配。永久学习资格、剧情事实、已完成任务和无偿基础技能保留。
- 不在战斗中重分配。任务入口先显示所需机制，允许返回整备；“反再生”不能成为只能靠不可逆培养解决的门槛。
- 最低队伍不带医者时，岩术与防御、应急药品、据点恢复提供可行路径；不能把米娅作为所有后期任务的隐性必需条件。

## 3. 回合战斗与任务目标

### 3.1 命令与回合顺序

固定命令为攻击、防御、技能、物品、撤退；有任务机制的战斗追加“救援”“推进”或“抑制”上下文命令。这些任务命令各消耗使用者一个动作，不消耗 MP／TP，不作为可学习技艺。

每回合流程：展示敌方意图 → 为全部队员选择指令 → 按敏捷排序执行 → 状态与目标计量结算 → 判断胜负 → 进入下回合。

- 行动按本回合开始时的 AGI 降序；同敏捷依次为队伍阵位 1–4，再敌群位置 1–4。没有随机速度浮动。
- 本回合中提高敏捷在下回合改变排序，不能插队产生额外动作。
- 战斗初版关闭伤害浮动、随机命中、随机暴击、随机状态概率和额外行动。所有可用技能命中率 100%，目标免疫必须提前可见。
- 普通防御减少本回合受到的伤害 50%，在该角色本回合实际行动前即生效；不能因敏捷较低失去防御作用。
- 角色失能后不执行未完成动作；复苏后本回合不补回已经丢失的动作，下回合正常行动。
- 物品在行动实际执行时扣除。目标提前失效时，治疗／物品按当前缺失 HP 从高到低转给合法队员；攻击按敌群最前合法目标改选，规则在目标说明中显示。
- 可撤退的普通遭遇成功率为 100%，无奖励，保留已经花掉的物品和 MP。关键战斗不能撤退，进入前明示；失败后仍可免费重试或返回准备。

### 3.2 敌方意图

意图包含动作类别、固定目标或可选目标范围、关键机制、蓄力／阶段信息。例如“下回合开始前：对队伍阵位 1 重击；若失能则改为最前存活者”“回合结束为再生守卫恢复最大 HP 的 8%”。

意图生成与展示不消耗随机数、不改变 HP 和任务计量。显示内容不承诺跨回合的精确伤害，玩家可改变状态、防御和目标生死；战斗 HUD 根据当前状态重算可解释的预估。

关键对手半血触发换阶段，当前回合已公开动作保持，下一回合才采用新模式。无法行动时显示“动作被中断”；不得悄悄换成另一种攻击。免疫定身、护送目标不可被治疗等限制在敌人或目标详情中明示。

### 3.3 五类目标模板

下面是首轮参数模板。具体战斗可以覆盖时限、护送 HP 和敌方目标伤害，但入口、战斗 HUD 与实际判定必须使用同一份数据。

| 目标 | 默认参数与玩家动作 | 胜利 | 失败 |
| --- | --- | --- | --- |
| 击退 `defeat` | 指定必须击倒的敌人 ID | 全部指定敌人失能，且至少一名队员可行动 | 全队失能 |
| 限时救援 `rescue` | 10 回合；进度 0–100；救援动作＋25 | 第 10 回合结束前，阻截者全部失能且进度 100 | 全队失能，或截止时未完成 |
| 独立生命护送 `escort` | 目标独立 HP；路线 0–100；推进动作＋25 | 路线 100，目标 HP 大于 0，至少一名队员可行动 | 目标 HP 为 0，或全队失能 |
| 撤离窗口 `evacuate` | 守过 4 回合；可以打断蓄力或减少人数 | 第 4 回合结算后林恩可行动 | 全队失能；指定关键目标被摧毁 |
| 设施压制 `suppress` | 初始压力 3；抑制动作－2，下限 0；回合结束当前压力大于 0才被动＋1 | 回合结束压力 0 累计连续 3 回合，或击破核心；至少一名队员可行动 | 回合结束压力达到 8，或全队失能 |

救援进度可以在阻截者存活时推进，但敌人未清除不能完成。阻截者全灭不自动结束救援战，玩家仍需要分配动作完成目标。护送目标不是第五名队员，不使用角色经验、队伍治疗、复苏和装备。

设施压制在回合结束时先判断当前压力：大于 0时被动增长 1，已压至 0时不被动回涨；敌方有明确预告的干扰动作仍能主动加压。随后检测“连续 0”，任一回合大于 0 重置连续计数。压到 0 后仍需维持三回合并处理敌方干扰，不能立即胜利。核心击破路线保留给输出培养，压制路线保留给控制与协作培养。

### 3.4 目标侧效、护送保护和判定

- 救援、推进、抑制以及敌人攻击护送目标在动作结束后一次性更新独立目标状态，再统一判断；不能先逐项判胜再继续扣 HP。
- 焰术与装备中的“额外压制”只在 `suppress` 生效，其他场合不额外造成伤害；从不替代任务本身要求的证据或救援准备。
- “护送阵”使本回合下一次护送目标受到的伤害减半，不叠加；再次施放仅刷新，目标计量旁显示保护次数。
- 普通医术不能治疗独立护送 HP。任务维修药包每战最多用一次，消耗一份药品，恢复护送最大 HP 的 25%；入口显示这一限制。
- 已完成的救援准备只在开战初始化时增加目标最大 HP、初始进度或其他声明值。重试恢复同一初始条件，不重复累加。
- 目标 HP 为 0、设施压力达到终止阈值等不可挽回的任务失败优先于击杀胜利；接着检查目标胜利，再检查全队失能，最后检查时限。所有胜利都要求至少一名队员可行动，撤离额外要求林恩可行动。
- 第 10 回合的最后一个动作完成救援可以获胜；第 10 回合结束后不能再补做动作。敌我同时全灭视为战斗失败，可以免费重试。

### 3.5 基准公式与状态

用于下面技能表的单次参考量：

```text
A = max(1, 4 × 使用者 ATK − 2 × 目标 DEF)      # 普通物理攻击
H = max(1, 4 × 使用者 MAT − 2 × 目标 MDF)      # 普通共鸣攻击
C = max(1, 2 × 使用者 MAT ＋ 4 × 使用者等级)  # 单体恢复参考
```

倍率在最终伤害取整前应用，最后向下取整、最低伤害为 1。敌方没有低于 0 的防御。百分比状态不无限叠加：同类只保留最强数值与最新持续时间，不同来源的总伤害减免上限 70%。普通防御包含在上限中，避免防御＋技能产生完全无伤。

| 状态 | 首轮定义 | 信息与限制 |
| --- | --- | --- |
| 烧灼 | 每回合结束伤害为施术时 `0.2H`，持续 2 回合 | 伤害在施加时锁定；同类不叠加 |
| 灼封 | 再生量减半，持续 3 回合 | 不削减普通医术；敌人无再生时提示无额外效果 |
| 减速／疾风 | AGI－20%／＋20%，持续 2 回合 | 下回合改排序；同类不叠加 |
| 迟滞 | 下一次非防御攻击伤害－30%，持续最多 2 回合 | 攻击执行即消耗；不减少固定设施增长 |
| 破甲／蚀术 | DEF－25%／MDF－25%，持续 2 回合 | 可以净化；数值下限保留 |
| 石衣／护符 | DEF＋25%／MDF＋25%，持续 2 回合 | 不额外增加独立护送 HP |
| 定身 | 丢失下一次动作，持续到动作轮次结束 | 每个目标每战最多生效一次；免疫者明示 |
| 净化保护 | 抵抗下一次负面状态，持续最多 2 回合 | 抵抗后消耗；不阻止剧情污染和任务失败 |
| 失能 | HP 为 0，停止行动 | 可在战斗中复苏；不等同剧情死亡 |
| 持续伤势 | 战斗外保存的伤势标记 | 只在据点诊疗，不由普通治疗清除 |

持续时间在施加回合末不扣除，从下一个回合末开始扣除。先结算同回合烧灼和再生，再进行统一目标判断；再生无法使已失能目标复活。每战 TP 从 20 开始，战后不保存；普通攻击获得 10 TP，防御获得 5 TP；不按随机受击积累 TP。TP 技能不返还 TP。

安全据点基础休整免费，恢复队伍 HP、MP、失能并清除战斗状态。休整不补充钱币和药品，不清除持续伤势。每个危险区前都能返回一个可用据点。

### 7.2 伤势

持续伤势分为“行动受限”“共鸣疲劳”“污染后遗”三类，角色同时最多一项，分别建议 HP 上限－10%、MP 上限－10%、MDF－10%。伤势不追加每步掉血，不自动恶化致死。

伤势来源只限明确的剧情结果，不能由每次战败随机获得。诊疗可付钱，也可选择一次非战斗义务任务作为替代；剧情要求等待的重伤人物，在下一场强制战斗前由代班、时间跳跃或恢复事件处理。

米娅在队不会免除所有费用与后果；她提供治疗方案与人物场景。玩家不带米娅时，公共诊所仍可处理基础伤势。永久死亡不能用诊疗菜单恢复。

### 7.3 防止资源软锁

危险区免费最低应急包按“本任务首次进入”发放，领取收据保存。失败快照重试复原同一包，不能离开重进重复领药。若撤退已经消耗包且无库存，可选择回据点领取任务限定的借用包：只用于该任务、不可出售、不转为永久库存；完成后余量收回。

没有资源的玩家仍能：休整 → 重新培养 → 调整队伍 → 选择慢路或劳动替代 → 获取必要任务药包 → 再次挑战。安全出口降低效率和奖励，不抹去人物牺牲与已发生的剧情责任。

## 8. 关系、选择与长期事实

### 8.1 关系记录

关系不采用赠礼刷满的 0–100 单值。每名同伴记录三个个人任务阶段、已兑现承诺、发生的冲突与是否愿意参与当前任务。

阶段为未开始、旧伤、冲突、交接；协作资格在第三个“交接”任务完成后获得。队伍可用状态为未加入、可用、暂离、永久离开、死亡；永久离开与死亡是不同结果。任务失败可出现另一种交接结尾，不直接删掉整个人物的后续内容。

日常对白从具体事实派生，例如“公开了运输账册”“隐瞒样本来源”“完成诊所义务”。展示界面可以用“信任／保留／冲突”描述当前关系，但显示标签不是独立权威值，也不用于暗中判死。

### 8.2 选择结构

选择定义至少包含：稳定 ID、章节、必要背景、选项文字、可见条件、风险提示、资源变化、写入事实、下一任务节点。条件不足时解释真实缺失项，不显示一个没有原因的灰按钮。

一般不可逆选择先明确说明人物或成果风险，再允许确认。死亡、永久离开和无补救机会的毁证需要独立二次确认；提示具体后果范围，不使用模糊的“是否确定”。读旧手动档可以选择别的路线，不把这种操作定义成违规。

### 8.3 三条因果链的事实例子

| 链 | 按时间记录的事实 | 实际影响 |
| --- | --- | --- |
| 通信 | `contact-address-kept` → `relay-protocol-set` → `disaster-register-kept` → `independent-records-checked` → `civil-relay-network-ready` | 接应、名单核对、独立证人、最终撤离条件 |
| 研究 | `early-observation-kept` → `sample-origin-recorded` → `anti-regeneration-study`＋`rescue-exit-anchors` → `public-research-procedure` → `safe-shutdown-tested` | 反再生、旧井救援、紧急关闭资格 |
| 信任 | `reed-language-basic` → `guide-testimony-respected` → `wetland-route-surveyed` → `community-passage-agreed` → `alternative-supply-route-ready` | 通路、证据、联盟补给方案 |

补救使用独立、在剧情登记表声明的事实，可以满足后续“存在通信渠道”，不能把未发生的 `contact-address-kept` 改成已发生，也不能删掉早期失联年表。条件表达“功能上具备”与“曾经发生”时必须区分，不临时增设同义别名。

事业结局资格由任务成果、世界条件与人物状态组成；界面显示已获得资格和缺失条件。“隐退幸存”始终可选。世界结局由分权、监督与停机条件判断，不使用隐藏累计善恶分。

## 9. 内容 ID、数据表和最小接口

### 9.1 命名与唯一来源

英文 ID 与中文名称分离；显示名修改不改变存档。ID 按内容类型登记，章节战斗冻结为 `c1-main-01` 至 `c7-main-06`、`c1-opt-01` 至 `c7-opt-02`。地图采用剧情稿固定 ID，例如试玩的 `c1-home`、`c1-post`、`c1-yard`、`c1-market`、`c2-road`、`c2-pump`；主线任务沿用所属主线节点 ID，地区支线采用 `cN-side-*`，个人任务和事实均使用剧情稿的规范 ID。奖励收据使用 `reward-*`。不同内容类型按各自命名空间映射，不能为同一事实增设第二套前缀别名。

MZ 数字编号映射登记在未来工程的 `data/EmbersRegistry.json`；新增只追加、不复用旧编号。人物、职业、技能、状态、装备、敌人、敌群、公共事件、地图、开关、变量各自有独立映射类型。编号区间与事件调用细节由 Windows 交接文档统一维护，本文件不另建一套区间。

永久剧情状态权威来源为 `$gameSystem._embers`。事件用的开关与变量只作只读镜像；剧情修改通过集中命令更新权威状态，再刷新镜像。原生角色、背包、金币与地图位置仍使用引擎标准对象，不把这些数据复制一遍变成两份资产账本。

### 9.3 概念数据形状

以下为接口约定，不是当前工程可运行代码；MZ 与 Godot 可保留同一语义，不要求同一序列化语法。

```text
EncounterDefinition {
  id, chapterId, troopId, objectiveType,
  objectiveParameters,
  actionEffectsByStableSkillId,

QuestDefinition {

  id, chapterId, contextText,
```

事实条件只使用明确存在的事实、任务阶段、人物状态和当前资源。首版条件为 `all`、`any`、`not` 三种组合，避免在事件脚本中散落不同版本的条件。

队伍 HP／MP、技能、装备、物品、金币、地图和位置由原生存档对象保存；永久事实不在战斗动作中直接写入，回到地图的结算公共事件一次性提交。

### 9.5 两个插件的最小调用面

| 调用 | 输入 | 输出／职责 |
| --- | --- | --- |
| `Story.RecordFact` | factId、sourceId | 按已登记定义写事实，刷新开关／变量镜像 |
| `Story.AdvanceQuest` | questId、stageId、sourceId | 推进合法阶段一次，校验前置与收据 |
| `Story.SetActorStatus` | actorId、statusId、sourceId | 更新人物状态并同步原生队伍 |
| `Story.AppendTimeline` | entryId、variantId | 加入登记的结果模板，相同 entryId 不重复写入 |
| `Story.GrantReward` | rewardId、sourceId | 发放登记奖励并保存收据，不接收任意金额 |
| `Story.Checkpoint` | checkpointId | 保存独立自动槽；失败保留待提交状态 |
| `Story.OpenJournal` | tabId | 打开年表、任务或人物页，不改变剧情 |
| `Battle.ConfigureEncounter` | 稳定 encounterId | 载入目标／敌群／意图／撤退规则，捕获战前快照 |

剧情奖励与最低等级补足由首胜公共事件结算。普通钱币与普通掉落由原生胜利结算承担，但同一奖励项只能选择一种所有者，不能原生与公共事件各发一次。后续保存失败不能再次执行原生战斗胜利奖励。

## 10. 存档、重试与失败处理

### 10.1 存档位置与内容

五个手动存档位与一个独立自动位。列表显示林恩年龄、年份、章节、地图、当前任务、游戏时长和内容版本。自动槽不能覆盖手动槽，手动槽不能误作自动槽。

仅在地图的安全状态保存：不在战斗、奖励弹窗、正在移动的强制事件、未提交剧情选择和存档失败待处理期间开放手动保存。自动点为章节交接、危险区前、重大选择结算后。普通对白不逐句保存。

存档包含原生游戏对象以及上一节永久状态、已完成目标判定记录和奖励收据。不保存无限战斗日志；每场结果只记结局、回合数、目标完成情况与人物结果。活动重试上下文不产生长期历史副本。

### 10.2 战前快照

快照捕获队伍阵位、角色等级与已学技能引用、当前 HP／MP／状态、装备、物品与钱币／补给／药品、目标初值、战斗配置 ID、返回位置和进入事件上下文。

快照不能复制整个 `$gameSystem`，也不能嵌套上一份快照。永久任务事实在进入战斗前已经提交；战斗期间只修改临时战局，胜负返回地图后集中提交。

普通失败提供两个免费按钮：

- **原配置重试：** 恢复进入前的消耗与队伍状态，同一敌群、意图、目标初值，再次开始。
- **返回准备：** 同样恢复进入前状态，返回指定安全整备点；可免费重配技能和队伍，再进入同一任务。

这两项恢复药品不会额外收费，重试不重复领任务包、不重复获得经验、金币、物品和年表条目。成功、撤退或主动放弃的结算后清除活动快照。主动撤退保留已经消耗的资源，不能用撤退恢复物品。

### 10.3 剧情不可逆与读取旧档

剧情死亡、永久离开、牺牲和毁证在当前进度内不可撤销。悲剧终局画面提供读取手动档、返回标题和查看年表。读取较早的手动档后，可以重新选择；不封存人生、不拒绝旧档覆盖。

无需迁移当前网页项目的 localStorage 或卡牌存档。试玩 `campaignType=demo`，正式版为 `full`，不能直接将试玩进度装入正式章节；试玩可另存完成纪念记录，但不当作正式游戏进度。

### 10.4 保存失败与版本不兼容

- 保存成功前保留已经算出的待提交结果，不重新执行选择、奖励或原生战斗胜利流程。
- 失败提示“存档未写入”，提供重试保存和返回上一已保存进度；不能继续推进后误认为已经保存。
- 采用引擎提供的保存与备份机制，不手写破坏原生存档文件的覆盖逻辑。若自动保存失败，五个手动槽继续保留。
- 坏档或较新版本不兼容时只提示与隔离，不静默重置、不写空档覆盖。
- 首版只承诺同一内容版本的读取；未来迁移按 schemaVersion 增加明确步骤，保留原档副本。测试版缺内容时直接拒绝读取，说明原因。

## 11. 界面、操作与可读性

本节采用 `game-ui-ux` 的菜单栈、初始焦点、事件驱动 HUD 和颜色外提示原则。只规划引擎无关行为，不在当前环境制作界面。

### 11.1 界面布局

以 1280×720 为布局参考，窗口与全屏均保留完整内容。不同屏幕采用等比缩放与黑边，不裁切按钮或扩大地图可视范围获得不同情报。正文字号建议 24，提供 28 的大字模式；文字换行不遮挡选项。

地图 HUD 只显示当前主线、可选准备、钱币／补给／药品和菜单入口，不长驻六人全部属性。地图关键交互使用文字名称与图标提示，可见敌人显示与任务相关的类别，不把所有隐藏数值写满屏幕。

战斗 HUD 固定显示：胜利目标、时限／进度／护送 HP／压力、回合数、队伍 HP／MP／TP、敌方意图和状态。任务危险计量改变时以文字和图标提示原因。全灭／护送失败／超时分别说明失败原因，不能只出现“战败”。

### 11.2 菜单栈

```text
地图 → 主菜单 → 队伍／技能／装备／任务／人物／年表／地图／系统
任务 → 任务详情 → 已知风险或关联年表
系统 → 保存／读取／设置／返回标题
战斗 → 指令 → 技能／物品 → 目标选择
任意危险选择 → 确认对话框
```

取消只回到上一层，不同时关闭全部菜单。顶层接收输入，下层暂停交互；关闭确认框后恢复之前焦点。每页打开时有明确默认焦点，技能与目标选择切换时保留该角色上次合法位置。

战斗动画和结算期间锁住重复提交，不允许双击消耗两份药。HUD 由资源、任务、目标与人物状态变化事件刷新，数据变化与显示来源一致；不从年表文字反推游戏事实。

### 11.3 键鼠

- 方向键移动／切换焦点；确认用 Enter、Space 或 Z；取消用 Escape 或 X；菜单用 Escape 或 X。
- 鼠标单击移动目标或选择控件，确认危险选择仍需独立按钮；右键取消上一层。
- 所有主要功能可以只用键盘完成，鼠标移入不取消键盘焦点。
- 输入配置以 MZ 原生习惯为默认，首版不加入自定义手柄或复杂重绑界面。
- 禁用选项保留说明入口；灰色之外增加锁图标和具体缺失条件。

### 11.4 任务、人物和年表

任务分为主线、地区支线、人物任务、已完成。每项显示当前步骤、地点、可选准备、奖励类别与关闭时点；完成任务保留结果摘要，不要求重播对白才能找信息。

人物页显示当前可用状态、已兑现承诺、个人任务阶段、协作技能、伤势和已知冲突。死亡者保留人物页与年表，不从世界记录中删除。

年表按章节和年份查看，记录时间跳跃、重大选择、人物变化和世界变化。只说明已经发生的因果，不提前泄露全部未来结局。结局资格页则明确列出已满足与真实缺失条件，避免要求玩家外查攻略。

### 11.5 可访问性

状态由图标＋文字＋颜色共同表达；HP 低、目标受损、证据缺失不能只靠红绿区别。界面提供文字速度、瞬间显示、战斗动画速度、音乐／音效音量、关闭画面震动。重要剧情不靠音效独立传递。

中文文本外置或集中登记，技能效果与费用来自定义数据，避免不同菜单维护相互矛盾的描述。系统提示简短直接，人物对白保留语气；不把版本号、变量编号和脚本名称写进玩家剧情。
